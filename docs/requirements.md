# 1. プロジェクト概要

本作は「多層・創発型オートメーション防衛ゲーム」です。ゲームの内部データ空間は3D（X/Y/Z ボクセルグリッド）として保持しますが、**プレイヤーへの表示は真横からの2Dスライスビュー**とします。これにより、Dwarf Fortressのような「断面図」視点で地下世界を直感的に把握でき、高い戦略性と探索の楽しさを両立します。

未知の地下空間を掘り進め、高低差と物理法則（背圧・重力）を利用したエネルギー網を構築し、深淵から迫る敵を自律型スウォームと空間制圧兵器で迎え撃つシミュレーションゲームです。「物理的な配線構造による創発的ルーティング」と「掘削によるリスクとリターンのジレンマ」をコアとします。

# 2. ターゲットユーザー
- FactorioやSatisfactoryなどの自動化・ロジスティクス構築ゲームのファン
- Dwarf Fortressなどの断面図視点のシミュレーションが好きなプレイヤー
- RimWorldなどのコロニーシミュレーションで、創発的なトラブルシューティングを楽しむ層

# 3. 機能要件 (Functional Requirements)

## 3.1 表示・視点（2Dスライスビュー）
- ユーザーとして、3Dボクセル空間の任意のY層（深度）を断面図として2Dで表示できる。
  - **受け入れ基準**: 現在の表示レイヤー（Y座標）がUIに表示され、上下キーで切り替えられること。
- ユーザーとして、各ボクセルの種類（空洞・岩・土・パイプ・ワーカー・敵）が色やアイコンで区別できる。
  - **受け入れ基準**: ボクセル種別ごとに異なる色/シンボルで描画されること。

## 3.2 空間トポロジーによる創発的ルーティング
- ユーザーとして、パイプを配置することでエネルギー網を構築できる。
  - **受け入れ基準**: パイプを2Dグリッド上でクリック/選択により配置・除去できること。
- ユーザーとして、パイプの分岐・高低差で流量・背圧・重力（下優先）を物理的に制御できる。
  - **受け入れ基準**: セル・オートマトン演算によりエネルギーの圧力値が視覚的に変化すること。

## 3.3 掘削と探索（Risk & Reward Exploration）
- ユーザーとして、ボクセル空間（有限マップ）の壁を掘り抜くことで未知の鉱脈や地下空洞を発見できる。
  - **受け入れ基準**: 未探索ボクセルは「霧」として表示され、掘削後に内容が開示されること。
- ユーザーとして、掘り抜いた空間が敵の侵攻ルートになるリスクを管理する必要がある。

## 3.4 空間制圧型の防衛
- ユーザーとして、ボクセルに防衛施設を設置できる。
  - **受け入れ基準**: 防衛施設の影響範囲（キルゾーン）が2Dグリッド上に視覚表示されること。

## 3.5 自律型スウォームとインフラ
- ユーザーとして、空間に「掘削」「建設」マーカーを置くことで、自律型ワーカーに作業を指示できる。
  - **受け入れ基準**: ワーカーが2Dグリッド上でフローフィールドに従って移動・作業することが確認できること。

## 3.6 敵の侵攻
- 敵として、防衛網を避け壁を掘削してコアへ侵攻できる。
  - **受け入れ基準**: 敵エンティティが2Dグリッド上でパスファインディングしながら移動すること。

# 4. 非機能要件 (Non-Functional Requirements)
- **パフォーマンス**: 数千単位のワーカー・エネルギー流（セル・オートマトン）が60FPSで動作すること（データ指向設計）。
- **グラフィックス**: 2Dタイルベースの描画。Canvas2D API（wasm-bindgen経由）または Bevy 2Dスプライト機能で実装する。3Dレンダリングは使用しない。
- **プラットフォーム**: **WebAssembly（WASM）専用**。ネイティブビルドは提供しない。
- **操作性**: マウスクリックによるボクセル選択・操作、キーボードによるレイヤー切替。

# 5. 制約事項
- **技術スタック**: Rust言語 + WebAssembly（`wasm32-unknown-unknown`ターゲット）。
- **レンダリング**: 3Dレンダラー（Bevy PBR/3Dカメラ等）は使用しない。2D描画に特化した軽量な実装を採用する。
- **物理エンジン**: 汎用3D物理エンジンは使用しない。セル・オートマトンとフローフィールドを自作実装する。
- **スコープ（保留機能）**: 「熱と冷却の概念」および「遺物による局所的な物理法則のハック」はMVPスコープ外とする。
